# mtkprof (version to be chosen): the 10053 reader

Draft. The owner decides the version and whether to release.

mtkprof now reads Oracle optimizer traces (event 10053). A file of 10053
dumps opens in a tab of its own with a view that makes it navigable and says
what its parts are. It reads the trace; it computes nothing from the costs.

## Moving from v0.7.0

- **Caches**: caches written by v0.7.0 are rebuilt on first open
  (`CacheIndexFormat` 8). A file with optimizer dumps no longer counts them
  as unknown lines.

## The 10053 view (desktop and `mtkprof serve`)

- A file that holds optimizer dumps and no 10046 record opens as a 10053
  tab. The folder picker opens it as a tab beside the set of 10046 files it
  was selected with; given with 10046 files in one request, it is left out of
  the set with a note and a button that opens it.
- The outline lists the dumps of the file and, for the open one, its
  sections in file order down to the join steps, with line counts.
- The text is the trace's own lines, Formatted or Raw. Formatted turns
  banners into headings, tints the key lines, folds the noise (default
  parameters, the second parameter dump, the adaptive plan's re-costing,
  repeated text) with the line count of each fold, pretty-prints the SQL and
  shows the plan table as a plan.
- Landmarks: verdicts of the cost-based transformations, Final cost, Best::
  AccessPath and JoinMethod, aborted join orders, hint errors and refused
  transformations, each kind with a switch, stepped through with `]` and `[`.
- Costing runs show the verdict of their iteration; the run that gave the
  final plan is labelled; a run whose text repeats an earlier one is marked
  "same as run N" and folded.
- Every `UNPARSED QUERY IS` statement pretty-printed with a diff against the
  previous version. The final plan with *Open in plan viz*.
- A guide that says what the section and the line under the cursor are, each
  entry backed by a named source; where there is none it says so.
- Search in the whole dump (literal or regular expression) with the hit
  count on each outline row, a where-am-I path, a line map, notes and
  bookmarks on lines.
- A statement of a 10046 tab shows a 10053 mark when another open tab holds
  a dump with the same sql_id; the mark opens that dump and the dump's row
  links back to the statement.
- The folder picker tags 10053 files (*10053*, *10046 + 10053*) and counts
  their dumps; its filter reads *Only SQL and optimizer traces*. The Reports
  page of a 10053 tab has the text digest, the JSON document and the
  standalone HTML.

## Command line

- `mtkprof report file.trc` prints a digest of an optimizer trace: per dump the
  SQL, the altered parameters, the peeked binds, the outline with line
  numbers, the landmark lines, each version of the SQL, the final plan and
  the hints. `mtkprof html file.trc` writes the view with the digest inside.
  `-redact-binds` and `-binds none` apply to the bind sections of the digest
  and of the HTML; the view in the app shows the values of the file.
- `mtkprof lint` lists the 10053 line kinds and the dumps.
- A trace with 10046 and 10053 written together still opens as a 10046 trace.
  Its dumps are no longer unknown lines, and the trace facts note them.

## Limits

- 19c is tested. Another version opens best effort, and the view says "read
  with the 19c rules" and how many lines fell outside any known section.
- A file with 10046 and 10053 interleaved is not read as 10053 yet.
- The app does not produce the trace; the assistant and `mtkprof mcp` do not
  open 10053 files; Compare and Cut are not offered on a 10053 tab; a 10053
  file cannot be followed live; `pivot`, `export`, `plan`, `refscript`,
  `compare` and `brief` stop with one line for a 10053 file.
