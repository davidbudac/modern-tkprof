# mtkprof v0.4.0

Trace sets as a first-class input, live sessions that update in place, and a
correctness fix for idle waits inside calls. Caches written by v0.3.x are
rebuilt on first open (`CacheIndexFormat` 3).

## Trace sets (several files or a directory)

- Files side panel: every source trace with size, lines, contexts, pid,
  time span and PX / chain markers; select one or several (click = only
  this file, ⌘/Ctrl-click, Shift-click, All / None / Invert), `#files=0,2`.
- Every view follows the selection: Overview ledger and lanes (whose time
  axis is the selection's span), Statements (new `api/statements` over a
  scope, with executions, waits, plans and the Context header), Findings
  (new `api/findings`), Sessions grouped by file, Lines, Pivot; top-bar
  counts read "13 of 59".
- Saved Pivot configurations can carry the file selection (by name) and
  clock-time windows.
- Response time of a set is the sum over its sessions (DB-time-like), with
  the wall-clock span shown next to it; percentages stay within 100 %.
- `testdata/sets/workload`: a 21-file directory set (4 concurrent sessions,
  PX slaves with stub chains, a 2-file chain, errors) generated on the lab
  by `run_gen.sh workload`.

## Live sessions

- `GET api/doc?rev=N` long poll (`X-Rev`, `X-Live`); the UI updates in place
  with a "live · rev N" badge and pause/resume, keeping scope and selection.
- Chains are followed in both directions while tailing: `TRACE CONTINUES
  IN FILE` switches to the next file, `TRACE CONTINUED FROM FILE` pulls in
  the earlier ones (local and remote).
- `mtkprof follow -serve`: the live report of a followed remote trace.
- Live spills keep a cursor index, so statement-scoped drill-downs work on
  live sessions.

## Correctness

- An idle-class wait inside a call (`PL/SQL lock timer` of
  `dbms_session.sleep`, `SQL*Net message from client` inside a fetch loop)
  is now counted once: it belongs to the call (`WaitEla`); between-call
  idle is the only idle. Two `sleep(1)` show 2.0 s, not 4.0 s. tkprof
  parity goldens are unchanged.

## Engine and CLI

- `mtkprof engine -idle D`: opt-in eviction of idle sessions.
- In-memory cache listing (`GET /engine/cache` no longer scans per request).
- Adaptive `V$DIAG_TRACE_FILE_CONTENTS` fetch ranges (50 000 → 400 000
  lines on fast links).
- `trace -since` accepts `3d` like the engine.
- `contexts=-` (no contexts) on every scoped endpoint.
- `make release` adds `mtkprof-lite-<os>-<arch>` (`-tags nooracle`, ~12 MB)
  for linux, aix and solaris.

## Lines, Pivot, misc

- Lines: search matches highlighted in rows, per-line Copy and permalink,
  "Jump to time" takes a clock time; Pivot: statement / event-only pickers.

## Verified on the lab (dbmint, 19.27)

Full `ref -db` equals the refscript bundle; `DBMS_SESSION` self-trace needs
`ALTER SESSION`; tracing a PDB session from `CDB$ROOT` works with
`CONTAINER_DATA=ALL`; the engine's db routes end to end with one password
prompt, including a tunnel killed mid-fetch and resumed byte-exact; a 2 GB
trace opens in 13 s with a 146 MB peak RSS (`docs/REMOTE.md`).
