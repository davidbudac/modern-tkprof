# The 10053 reader: plan

Written 2026-11-11. The format and the lab measurements are in `docs/trace-format-10053.md` (research of
2026-11-10). The decisions below were settled with the user on 2026-11-11 in a question-by-question review
(33 questions); they go into `docs/DESIGN.md` when the feature is built (§ Inputs still says "No 10053").

## Why

A 10053 trace is the optimizer's log of one hard parse: the statistics it read, the estimates it derived, the
transformations and join orders it weighed. It is hard to read as it comes: 18,523 lines for a two-table
statement with two subqueries, 93,620 for a ten-table join, no index, the same query block costed up to nine
times, every parameter printed twice. The tools that existed are a Windows tree viewer written for 10g (Sloot
and van der Ende, 2010), the Lab128 viewer (its download page is gone) and text search.

The first version is a **reader**: it makes the file navigable and explains what its parts are. It does not
compute anything from the costs.

## Decisions

### Scope

- **A reader, named "10053"** in the UI (the view, the mark on a statement), the docs and the CLI.
- **Input: a file that holds only 10053 dumps** (at least one dump, no 10046 record). This is how the traces
  arrive: taken separately for one or a few statements after a 10046 trace pointed at them.
- **A file with 10046 and 10053 interleaved is not read as 10053 in this version.** It opens as a 10046 trace
  as today. Two things change: the dumps' lines are no longer counted as unknown lines, and the trace facts
  carry a note ("2 optimizer (10053) dumps in this file, lines 54-18358 and 18734-27979; not shown as 10053
  yet").
- **19c is the tested version.** A file of another version opens best effort; the view's header says "read
  with the 19c rules; this file is 23.6" and the outline shows how many lines fell outside any known section.
- **Not in this version**: producing the trace from the app (turning the event on, `DBMS_SQLDIAG.DUMP_TRACE`);
  the assistant and `mtkprof mcp` (they do not open 10053 files); Compare and Cut on a 10053 tab.

### The view

A new view of its own, not a mode of the Lines view: the outline on the left, the text in the centre, the
guide on the right. Its look is agreed on a mock-up before the build (`docs/mockups/10053-reader/`).

- **Outline**, full depth: dump → phase (environment, transformations, costing, result) → query block →
  costing run → table / join order → join step. A node shows its line count; a join order node shows its own
  text from the trace (the tables, "aborted" or its cost).
- **Several dumps in a file**: the outline's top level lists them (sql_id, the first words of the SQL, the
  tables, line count, plan hash); one is open at a time. Two dumps of one sql_id are two entries, numbered in
  file order.
- **Centre: Formatted, with a Raw toggle.** Formatted is the trace's own lines in file order, dressed: banners
  become headings, landmarks are tinted, noise is folded, one-line SQL is pretty-printed, the plan table can
  show as a plan. Raw is the file untouched. Nothing is re-rendered as tables of numbers.
- **Noise folded by default**, each fold with its line count: the parameters with default values, the fix
  controls, the second parameter dump (`Optimizer state dump`), the adaptive plan's re-costing, repeated
  statement text.
- **Landmarks**: key lines marked in the text and listed, with next / previous keys: `Best:: AccessPath`,
  `Best:: JoinMethod`, `Final cost for query block`, `Join order aborted`, a bypassed or refused
  transformation, `Updated best state` / `Not update best state`, a hint with an error. The list is settled in
  the mock-up.
- **Costing runs**: each run shows the verdict the trace gives it and the run that produced the final plan is
  labelled. A run whose text equals an earlier one (addresses ignored) is marked "same as run N" and folded.
  This compares text; it does not read the numbers.
- **SQL**: every `UNPARSED QUERY IS` statement pretty-printed with the app's SQL formatter, with a diff against
  the previous version of the statement.
- **Final plan**: the dump's `Plan Table` in mtkprof's plan view (tree, predicates, query blocks), with "open
  in plan viz".
- **Guide**: fixed explanations per kind of section and line ("Access paths considered for this table; the
  line `Best::` is the one kept"), and a glossary of terms and codes as tooltips. An entry is written only when
  a named source (the trace's own legend, Oracle's documentation, Lewis, Breitling, Pagano) or the lab backs
  it; a section or term without one has no guide text. The sources are listed in the docs, not in the UI.
  Sentences about this trace's decisions, computed from its numbers, are not in this version.
- **Also**: notes and bookmarks on lines (desktop, as in the Trace pane, listed in Annotations); literal and
  regex search with the number of hits on each outline node; a where-am-I path above the text (dump › Costing
  › SEL$1BA63A14 run 3 of 9 › Join order 7 › Now joining MTK_CUST, each part a link); a line map beside the
  scroll bar (phases as bands, landmarks and hits as ticks, the visible range).

### Tabs and the link to a 10046 trace

- A 10053 file is **always its own tab** (desktop) or its own `serve` / report run. Given inside a set of 10046
  files it is left out of the set with a note.
- **A jump only**: a statement of a 10046 tab shows a "10053" mark when another open tab holds a dump with the
  same sql_id; the mark switches to that dump, and the dump links back. No data is joined. Desktop only (`serve`
  holds one session).

### Clients

| Client | What it has |
|---|---|
| Desktop, `mtkprof serve` | the view |
| Standalone HTML (`mtkprof html`, the default command) | the same view fed with the digest; where text is not included the centre says "1,234 lines not in this report (lines 2032-3265)" |
| Text (`mtkprof report`, the default command) | the digest |
| `mtkprof lint` | the 10053 line kinds and the dumps |

**The digest** is the trace without its noise, nothing computed. Per dump: sql_id and SQL, the altered
parameters and fix controls, the peeked binds, the outline with line numbers and line counts, the landmark
lines verbatim with their line numbers, each version of the transformed SQL pretty-printed, the final plan
with its predicates, the hints with their flags. `-redact-binds` and `-binds none` apply to the bind sections
(`Bind Info`, `Peeked Binds`) as they do to 10046 binds; literals in the SQL text and the predicates stay.

### Correctness

- **Best effort on what Oracle writes**: the format is undocumented free text that changes with releases; an
  unrecognized line stays readable where it is and is counted, and nothing is guaranteed for traces not seen.
- **Our own output is pinned**: every lab fixture has a committed outline and landmark list (a snapshot); a
  parser change that alters one shows in the diff. The 10046 golden tests do not change, for files with and
  without dumps.
- **Fixtures are real**, generated on the lab by `testdata/gen` (`sc_opt_*.sql`). The generator may create new
  objects in schema `MTK` (a partitioned table, a table without statistics): idempotent CREATE only, never
  DROP or TRUNCATE, as for the existing tables.

### Afterwards

Candidates without order or commitment, chosen after the reader has been used on real traces: a computed
summary per statement; decision views (transformation ledger, access paths per table, join order explorer);
the origin of a row estimate joined to the 10046 actual rows of the same plan; comparing two dumps; reading
the dumps of an interleaved file; a digest tool for the assistant and MCP; 21c and 23ai fixtures.

## Sequence

1. This plan and the format reference committed.
2. An interactive mock-up of the view on a real lab trace, light and dark, in `docs/mockups/10053-reader/`;
   the user approves or corrects it.
3. The build, in one run, committed to `main` in logical commits, pushed, reported once at the end. No
   release.

## The build (after the mock-up is approved)

- **Fixtures**: `sc_opt_*.sql` scenarios and their traces in `testdata/traces/19c/` (a statement with
  subqueries and binds; two statements in one file, one with a bad hint; a many-table join; missing
  statistics with dynamic sampling; a partitioned table; a parallel plan; a DML statement; an interleaved file
  for the note and the 10046 golden test).
- **Parser** (`internal/trace`): a dump runs from a `Registered qb: … (PARSER)` line outside a dump to `END SQL
  Statement Dump`; new line kinds for its lines; inside a dump a valid 10046 record keeps its kind. `lint`
  reports them.
- **Model** (`internal/opt`, pure Go, streaming): dumps, the section tree with line ranges, landmarks, costing
  runs with their verdicts and text hashes, the SQL versions, the plan table, hints, binds, altered
  parameters. Snapshot tests per fixture.
- **Peek** (`internal/peek`): a file's kind (10046, 10053, both) for the folder picker.
- **Engine**: a 10053 session (its own kind), routes for the outline, the landmarks, pages of lines and search
  with counts per node; `api/engine.openapi.yaml` and `desktop/src/engine/api.d.ts` in the same commit; the
  persisted outline bumps its format and `engine.CacheIndexFormat` with the guard tests.
- **Report**: the text digest; the digest in the JSON document for the standalone HTML; the redaction flags.
- **UI** (`web/src/lib`): the view, the guide and glossary data with their sources, the line map; the desktop's
  tab kind, the "10053" mark and jump, notes and bookmarks.
- **Docs**: DESIGN (§ Inputs; the facts-only rule gets its exception for the 10053 guide), ARCHITECTURE,
  DESKTOP, HANDOFF, the site's docs page; `make web`, `scripts/ci-local.sh`, screenshots.
